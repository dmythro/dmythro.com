Цей сайт — це моє CV і мої проєкти, яких стає дедалі більше. Увесь він лежить у відкритому монорепозиторії, де застосунки стоять поруч зі спільними пакетами. Я тримаю його як приклад того, як організовую код.

Почати раджу з пакетів. Вони написані на TypeScript, і жоден не має кроку збірки. Bun запускає файли `.ts` як є, а застосунки імпортують їх безпосередньо.

Ще я пробую тут нове, перш ніж пропонувати його команді. На це розгортання ніхто не чекає, тож з інструментом можна спершу пожити самому.

## Приклади

```sh
git clone https://github.com/dmythro/dmythro.com
cd dmythro.com
bun install
bun run dev
```

## Навіщо це

Почалося все з CV, яке я не хотів тримати у Word. Майже все, що з'явилося відтоді, я додавав, бо хотів спробувати це до того, як застосовувати в роботі: соціальні картки, що малюються під час збірки, CV, яке саме друкується в PDF, контент в окремому пакеті.

Сама ж сторінка має лишатися легкою, хоч би що відбувалося під час збірки. Це статичний HTML двома мовами, майже без JavaScript.

## Що всередині

### Застосунки й пакети

```text
apps/
  www2/        сайт на Astro
  www/         попередній сайт на Next.js
packages/
  locales/     тексти й ці статті, англійською та українською
  constants/   адреса сайту й посилання на соцмережі
  fonts/       Geist, лише латиниця й кирилиця
  cv-to-pdf/   друкує сторінку CV в PDF
  tsconfig/    спільні налаштування компілятора
```

Пакети пов'язує Bun workspaces, а завдання між ними запускає Turborepo. Форматування й лінтинг налаштовані одним конфігом Biome в корені.

### Пакети без кроку збірки

Ось усе, що потрібно, аби застосунок міг імпортувати пакет:

```json
{
  "name": "@dmythro/locales",
  "exports": {
    ".": "./src/index.ts",
    "./constants": "./src/constants.ts",
    "./mdx/*": "./mdx/*"
  }
}
```

`exports` вказує просто на файли `.ts`. Теки `dist` немає, скрипта збірки теж, і поруч із сервером розробки не працює жоден процес, який стежив би за змінами в пакеті. Виправляю одруківку в `packages/locales` — сторінка перезавантажується вже з нею. Скрипти й тести Bun запускає з того самого коду, і редактор бере типи звідти ж.

### Типово без JavaScript

Сторінки — це статичний HTML. Меню, перемикач теми й фільтри проєктів зроблені на CSS або кількох рядках вбудованого скрипта. Фреймворк завантажує лише одна сторінка, [калькулятор натягу струн](/uk/guitars/string-tension), і це острів на [Preact](https://preactjs.com/).

### Англійська й українська на кожному маршруті

Кожен маршрут має префікс `[locale]` і збирається обома мовами, разом зі стрічками й структурованими даними. Тексти — це типізовані об'єкти й MDX у пакеті `@dmythro/locales`. Якщо додати рядок англійською і забути про український, перевірка типів не пройде.

### Соціальні картки під час збірки

Кожна сторінка проєкту має власне зображення Open Graph. [takumi](https://takumi.kane.tw/) малює його з HTML-шаблону, поки збирається сайт, без headless-браузера й без сервісу зображень. Шрифти він бере з тих самих файлів Geist, які віддає сайт, тож збірка нічого не завантажує, а кирилиця на картці така сама, як на сторінці.

### Стрічки та машинозчитувані формати

Для кожної мови є RSS і JSON Feed, зібрані з тих самих даних, що й сторінки. Для програм, які сайт читають, а не показують, є `llms.txt` і `llms-full.txt`.

## Нотатки про рішення

Обійтися без збірки можна лише всередині репозиторію. Пакетові, який інші встановлюють з npm, однаково потрібні скомпільований JavaScript і декларації типів.

CV для завантаження — це сторінка CV, яку Chrome друкує зі стилями сайту для друку. Окремого документа я не веду. До речі, друк — єдине місце, де шрифти інші. Варіативний шрифт Chrome записує в PDF як малюнки, і текст, скопійований із CV, виходив як «q uality». Тепер стилі для друку беруть статичні файли Geist, а скрипт, який робить PDF, зупиняється з помилкою, якщо туди потрапив варіативний шрифт.

Попередній сайт досі лежить у репозиторії. Одразу після того, як я переписав його на Astro, обидві версії показували однаковий контент, тож фреймворки можна було чесно порівняти. У кожного свої сильні сторони, і з будь-яким сайт набирав 100% у PageSpeed. Далі я розвивав версію на Astro, а застосунок на Next.js лишився для довідки, і я його більше не підтримую.

Усе прегенерується і віддається з Cloudflare. Кількість зірок і завантажень для сторінок проєктів я забираю з GitHub і npm під час збірки. Браузер до API не звертається, і ключа, який треба було б берегти, на сторінці немає.
