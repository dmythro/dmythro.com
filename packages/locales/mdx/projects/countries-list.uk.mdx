Розкривний список країн — мабуть, найнудніше, що можна зробити, але в 2014-му я не знайшов даних, щоб його нормально заповнити. В одних списках були англійські назви без рідних, в інших були коди ISO, але не було телефонних кодів, а там, де було все, воно лежало в багатомегабайтному файлі, створеному для зовсім іншого завдання.

Зрештою я зібрав власний список, і відтоді ідея не змінилася: один запис на країну з кодом, назвою англійською й рідною мовою, столицею, валютою, телефонним кодом і континентом — і нічого зайвого.

## Приклади

```ts
import { continents, countries, getCountryCode, getEmojiFlag, languages } from 'countries-list'

countries.UA
// { name: 'Ukraine', native: 'Україна', phone: [380], continent: 'EU',
//   capital: 'Kyiv', currency: ['UAH'], languages: ['uk'] }

getCountryCode('Ukraine') // 'UA'
getCountryCode('Україна') // 'UA' — рідні назви теж працюють
getEmojiFlag('UA')        // '🇺🇦'
continents.EU             // 'Europe'
languages.uk              // { name: 'Ukrainian', native: 'Українська' }
```

Пакет містить усі коди ISO 3166-1 і кілька поза стандартом, має власні типи й не має залежностей. Редактор підказує ключі після `countries.`, а помилку в коді країни видно ще під час компіляції, тож вона не перетвориться на `undefined` під час виконання. Коди, що приходять із форми чи API, однаково треба перевіряти.

## Навіщо це

Назви країн знайти легко. Але полю вибору країни потрібні одразу чотири різні речі: код для збереження, назва для показу, прапор і телефонний код для поля з номером. Коли я брав їх із трьох пакетів, виходило три набори ключів, що не збігалися між собою, і ще окремий шар, щоб їх зіставити. Якщо ж усі поля лежать в одному записі, зіставляти нічого не треба.

## Чим відрізняється

Є й інші добрі набори даних, але кожен зроблений для свого завдання:

| Пакет | На що розрахований |
| --- | --- |
| `countries-list` | один типізований запис на країну: коди, рідні назви, столиця, валюта, телефон, континент |
| `i18n-iso-countries` | назви країн, перекладені багатьма мовами |
| `world-countries` | великий сирий набір даних із кордонами, координатами й альтернативними написаннями |
| `iso-3166-1` | перетворення між форматами кодів, і більше нічого |

Беріть `i18n-iso-countries`, якщо потрібна «Німеччина» японською. Переклад назв — його основне завдання, і він справляється з ним краще. Беріть `world-countries`, якщо потрібна географія. `countries-list` покриває поля, які зазвичай просить форма чи екран налаштувань.

На відміну від інших пакетів, цей є ще й для PHP на Packagist, згенерований з того самого джерела:

```sh
composer require annexare/countries-list
```

## Що всередині

### Валюти окремим імпортом

Повний список ISO 4217 з назвами англійською й рідною мовою, символами, числовими кодами й розмінними одиницями підключається через окремий підшлях:

```ts
import { currencies, getCurrency, getCurrencyByNumeric } from 'countries-list/currencies'

currencies.UAH
// { name: 'Ukrainian Hryvnia', native: 'українська гривня', symbol: '₴',
//   symbolNative: '₴', numeric: '980', decimals: 2 }

getCurrency('JPY')          // decimals: 0 — у єни немає розмінної одиниці
getCurrencyByNumeric('840') // USD, для банківських запитів з числовими кодами
```

Дані про валюти генерує скрипт з офіційного списку ISO 4217 і CLDR, руками я їх не правлю. Коли якась валюта змінюється, оновлення займає одну команду, а не пів дня ручних виправлень.

### Мінімальні мапи для простих випадків

Іноді потрібно кілька кілобайтів, а не весь набір даних:

```ts
import countries2to3 from 'countries-list/minimal/countries.2to3.min.json'
import languageNames from 'countries-list/minimal/languages.native.min.json'
```

### Формати поза JavaScript

Ті самі дані генеруються ще й у JSON, CSV і SQL, тож базу можна заповнити, не пишучи спершу скрипт імпорту. Файли входять до npm-пакета, окремо нічого завантажувати не треба:

```sh
mysql app_db < node_modules/countries-list/data.sql

head -2 node_modules/countries-list/countries.csv
# "Code","Name","Native","Phone","Continent","Capital","Currency","Languages"
# "AC","Ascension Island","Ascension Island","247","Africa","Georgetown","SHP","en"
```

## Нотатки про рішення

Валюти я виніс у `countries-list/currencies`, а не в кореневий експорт, бо повна таблиця ISO 4217 з рідними назвами й символами важить відчутно, а більшості застосунків, яким потрібен список країн, вона не знадобиться. З окремим підшляхом звичайний імпорт лишається легким, а налаштувати такий підшлях майже нічого не коштує, проте в більшості наборів даних його немає.

Стандарт ISO 4217 символів не визначає. У ньому є коди, числові коди й розмінні одиниці, а `₴` чи `¥` беруться з Unicode CLDR, окремого джерела, яке оновлюється за власним графіком. Якщо у валюти немає окремого латинського знака, у `symbol` потрапляє код ISO, а місцевий знак іде в `symbolNative`. Тому `CHF` лишається `CHF`, а `JPY` дає `¥` для латинського інтерфейсу і `￥` для японського. Одне поле було б простішим, але інтерфейсу потрібні обидва значення.

`getCountryCode` шукає не лише за англійською назвою, а й за рідною («Україна» → `UA`) та за поширеними альтернативними назвами на кшталт `USA` чи `UK`. Це один додатковий індекс у даних, зате набором можна користуватися у формах іншими мовами без власної таблиці відповідностей.

У третій версії я повністю переписав проєкт на TypeScript і ESM, у монорепозиторії на Bun workspaces. Усе в `dist`, включно з SQL, генерується з типізованих початкових файлів, тож виправлення даних — це одна зміна в типізованому джерелі, а раніше доводилося вручну синхронізувати чотири файли.
