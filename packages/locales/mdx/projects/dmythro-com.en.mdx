This site is my CV and my projects, and the list of projects keeps growing. All of it lives in a public monorepo, apps next to the packages they share, which I keep as an example of how I organize a codebase.

The packages are where I'd start reading. They're plain TypeScript with no build step: Bun runs the source as it is, and the apps import it directly.

I also try things here before I propose them to a team. Nobody is waiting on this deploy, so I can live with a tool for a while first.

## Examples

```sh
git clone https://github.com/dmythro/dmythro.com
cd dmythro.com
bun install
bun run dev
```

## Why it exists

It started as a CV that I didn't want to keep in Word. Most of what has been added since is there because I wanted to try it before using it at work: social cards drawn during the build, a CV that prints itself to PDF, content that lives in a package of its own.

The page itself has to stay light, whatever the build is doing. It's static HTML in two languages with almost no JavaScript.

## What's inside

### Apps and packages

```text
apps/
  www2/        the site, built with Astro
  www/         the previous site, built with Next.js
packages/
  locales/     the copy and these articles, in English and Ukrainian
  constants/   the site URL and social links
  fonts/       Geist, subset for Latin and Cyrillic
  cv-to-pdf/   prints the CV page to PDF
  tsconfig/    shared compiler settings
```

Bun workspaces link the packages together, and Turborepo runs the tasks across them. Formatting and linting come from one Biome config at the root.

### Packages with no build step

This is all it takes for an app to import a package:

```json
{
  "name": "@dmythro/locales",
  "exports": {
    ".": "./src/index.ts",
    "./constants": "./src/constants.ts",
    "./mdx/*": "./mdx/*"
  }
}
```

`exports` points straight at the `.ts` files. There's no `dist` folder and no build script, and nothing has to watch the package while the dev server runs. When I fix a typo in `packages/locales`, the page reloads with it. Scripts and tests run from the same source under Bun, and the editor takes its types from there too.

### No JavaScript by default

Pages are static HTML. The menu, the theme toggle and the project filters are CSS or a few lines of inline script. The one page that loads a framework is the [string-tension calculator](/en/projects/string-tension), which is a [Preact](https://preactjs.com/) island.

### English and Ukrainian on every route

Every route has a `[locale]` prefix and is built in both languages, feeds and structured data included. The copy is typed objects and MDX in `@dmythro/locales`. If I add a string in English and forget the Ukrainian one, the type check fails.

### Social cards drawn during the build

Each project page has its own Open Graph image. [takumi](https://takumi.kane.tw/) draws it from an HTML template while the site builds, with no headless browser and no image service. It uses the Geist files the site already serves, so the build downloads no fonts and the Cyrillic on a Ukrainian card matches the page.

### Feeds and machine-readable output

Each language has an RSS feed and a JSON Feed, built from the same data as the pages. For programs that read the site rather than display it, there are `llms.txt` and `llms-full.txt`.

## Design notes

Skipping the build only works inside a repository. A package that other people install from npm still needs compiled JavaScript and type declarations.

The downloadable CV is the CV page, printed by Chrome with the site's print stylesheet. I don't maintain a separate document. Print is also the one place where the fonts differ. Chrome writes a variable font into a PDF as drawings, and text copied from the CV came out as "q uality". The print styles use the static Geist files now, and the script that makes the PDF fails if a variable font gets in.

The previous site is still in the repository. Right after I rewrote it in Astro, both versions served the same content, which gave me a fair comparison of the two frameworks. Each has its strengths, and either one got the site to 100% on PageSpeed. I went on with Astro, and the Next.js app stays as a reference that I no longer maintain.

Everything is prerendered and served from Cloudflare Pages. The star and download counts on the project pages are fetched from GitHub and npm during the build. The browser makes no API calls, and there's no key in the page to protect.
